# Allodesigner LP: Allosteric binding pocket redesign

## Strategy description

This strategy focuses on redesigning the allosteric binding pocket of a biosensor to accommodate a novel target ligand. Rather than relying on rigid docking, the pipeline employs a sequence of state-of-the-art structural and sequence generation models. It starts by sampling varying conformers and positions of the new ligand within the pocket. Then, it utilizes diffusion models (such as RFdiffusion, RFdiffusion All-Atom, or RF3) coupled with LigandMPNN to generate diverse pocket sequences capable of hosting the ligand. The generated sequences are subsequently filtered through an intensive cascade of structure prediction (ESMFold, AlphaFold3, Chai-1, and Boltz2) and docking models (GNINA) to ensure structural integrity, stability, and high-affinity ligand binding.

### `binding_site_designer.py`
The main execution script of the pipeline. Given an input structure with a bound ligand, it performs a full binding site redesign around a newly specified ligand to optimize binding affinity. It orchestrates RFdiffusion, LigandMPNN, high-throughput filtering, and downstream structural validation.

**Arguments:**
| Argument | Description |
|----------|-------------|
| `--config` | Path to the YAML configuration file with pipeline parameters |
| `--output` | Path to the output directory |

```bash
python binding_site_designer.py --config basic_config_bsd.yml --output results/
```

**Arguments:**

| `--input_csv` | Path to the CSV file containing the generated sequences |
| `--output_folder` | Path to the folder where predicted PDB files will be saved |


### `functions_bsd.py`
A comprehensive module containing all the background helper functions used by `binding_site_designer.py`. Includes functional blocks for structure parsing, executing RFdiffusion/LigandMPNN via CLI, calculating 3D clash/RMSD/pLDDT metrics, and formatting inputs for Chai/AlphaFold/Boltz.

> Imported directly as a module — not executed standalone.

### `ligand_sampling.py`
Prepares the binding site for redesign by taking a new input ligand (as a SMILES string) and an existing receptor structure. Samples low-energy conformers using RDKit and stochastically positions them within the receptor pocket via minor rotations and translations, providing diverse starting states for the diffusion models.

| `--structure` | Path to the reference receptor PDB/CIF file |
| `--output` | Path to the output directory |
| `--n_confs` *(optional)* | Number of RDKit conformers to generate (default: `5`) |
| `--n_pos` *(optional)* | Number of positional variations to sample (default: `5`) |

## Pipeline description

### Generate redesign info
First, the input structure is processed to gather information relevant to the execution of the pipeline and the evaluation of the results:
- Two kinds of sequences are retrieved from the PDB file: `sequence_coordinates` consists of the residues for which coordinates are found within the files, `sequence_seqres` contains the complete sequence of the protein provided in the SEQRES section of PDB files. In case this section is not present, `sequence_seqres` takes the value of `sequence_coordinates`. This is done to account for missing residues in the structure that can later cause indexing and chain break issues. Other relevant info like sequence length, missing positions... is also gathered.
- A DSSP string for the structure in case a secondary structure preserving approach needs to be implemented.
- The active site, the region where the redesign will occur, is defined either manually by the user (by providing a list), or automatically. In the latter case, a PyMOL function extracts a list of all the residues found within a sphere of radius `first_shell_distance` Å centred on the ligand. A second shell, all the residues less than `second_shell_distance`, is also computed. Lastly, any residue indicated by the user specifically to be or not to be redesigned is included or excluded.

The active site definition is processed into:
- An RFdiffusion "contig map" — a syntax that tells RFdiffusion which regions must be preserved and how many residues must be designed to connect the regions.
- LigandMPNN JSON files that indicate which residues to preserve and edit, and introduce a bias towards or against certain amino acids.

### Sampling ligand positions
In their redesign process, both RFdiffusion and LigandMPNN use the ligand atoms as context. As a result, the ligand needs to be previously placed in a somewhat reasonable position before redesign. Although docking could be used, it would serve little given that A) the new ligand might differ greatly from the original pocket, and B) the whole pocket is going to be redesigned, rendering the docking invalid. Instead, a sampling approach using RDKit tools is used:

1. The structure of the ligand is obtained from a SMILES string using RDKit `MolFromSmiles` and `conformers` low-energy conformers are sampled using `EmbedMultipleConfs`.
2. These conformers are placed in the pocket by aligning with the original ligand (which is later removed).
3. `positions` random slight rotations and translations are applied to each conformer to further explore the design space.

After this, a number of PDB files equal to `positions` × `conformers` is obtained and used as input for RFdiffusion.

> **Note:** This module can be skipped by providing a folder named `ligand_sampling`.

> **Note:** This module is not strictly necessary when using RFdiffusion3 with a flexible ligand configuration, since it allows the ligand to move and adapt to the pocket directly in the diffusion process.

### RFdiffusion
Three different versions of RFdiffusion are implemented to benchmark against each other: RFdiffusion, RFdiffusion All-Atom, and RFdiffusion3.

The PDBs generated in the ligand sampling step (or provided by the user) are used as a starting point to generate `num_designs` designs using the contig maps generated in the previous section.

The RFdiffusion step can be skipped either by providing a folder containing pre-diffused structures, or through the `ligandMPNN_only` flag for a sequence-only redesign.

### LigandMPNN
LigandMPNN produces `MPNN_num_designs` sequences for each given input PDB from the previous step, using the JSON files generated at the beginning. At this point, the total number of sequences is `positions` × `conformers` × `RF_num_designs` × `MPNN_num_designs` × `n_batches`. For each input file, sequences are ordered by their MPNN score (a metric assessing model confidence) and the `top_n_MPNN` sequences are preserved and stored in a pandas dataframe.

### 1D filter
The sequences produced by LigandMPNN are checked through a 1D filter based on a sliding window. If within the window more than x instances of the same amino acid are found, the sequence is removed. This addresses a known tendency of LigandMPNN to produce streaks of amino acids like alanine and glutamate, which lack biological sense.

### ESMFold
The structure of sequences surviving the 1D filter is predicted using ESMFold. ESMFold is an evolution-based model trained to transform sequences into embedding vectors, which contain structural features recovered to reconstruct full 3D structures. ESMFold is known for its swift predictions at the cost of some accuracy compared to the most precise models.

### 3D parameters and filtering — round 1

**Parameters computed for each ESMFold structure:**
- **pLDDT** — model confidence on the predicted structure, extracted from the B-factor field of PDB files.
- **RMSD and TM-score** — with the original structure, to assess deviations from the reference. Computed using the `tmtools` package.
- **Clashes** — physically impossible inter-atomic contacts. Two atoms are considered clashing if their distance is too short for an interaction but too long for a covalent bond. Computed via `biotite` as a pairwise distance matrix.

Additionally, the ligand is docked into each structure using GNINA, a docking program that uses a Convolutional Neural Network as a scoring function — comparable in accuracy to traditional force-field scoring functions but orders of magnitude faster, enabling high-throughput docking. The best pose, `CNNaffinity` (binding affinity estimated by the CNN), and `CNNscore` (a 0–1 pose quality score) are saved as additional parameters.

**Filtering:**

First, structures not meeting the minimum thresholds set by `MIN_PLDDT`, `MIN_RMSD`, `MAX_RMSD`, and `MAX_CLASHES` are removed. Then, each metric is normalised between 0 and 1, and a global score is calculated through a weighted sum using the weights defined in `global_score_weights`. Structures are sorted by global score and the `top_n_score_ESM` candidates are preserved. An additional GNINA-based cutoff (`top_n_GNINA_ESM`) can be applied to further narrow down the candidates.

### Second prediction round (AF3/Chai + Boltz)
The sequences surviving the first filtering round are subjected to a second structure prediction round combining Boltz2 with either AlphaFold3 or Chai-1.

**Boltz2** is a cofolding model designed to excel at structure and ligand binding pose and affinity prediction. Beyond structure metrics, it outputs `affinity_pred_value` and `affinity_probability_binary` (a 0–1 probability that the ligand is a binder).

**AlphaFold3 and Chai-1** are state-of-the-art structural prediction methods. While AlphaFold3 excels at small molecule binding and protein–protein interactions, it is heavily dependent on MSA information, unlike Chai-1. They should be selected according to their respective strengths.

For each structure, both Chai and AF3 are executed twice: once without ligand (to assess structural quality directly) and once in cofolding mode (to predict ligand binding and assess structural changes induced by the ligand). All folding models can be provided with the original template and activated MSA usage through their respective flags in the config file.

### 3D parameters and filtering — round 2
At this stage there are three kinds of structures: Boltz, AF3/Chai, and AF3/Chai cofold predictions. For each group, the same parameters as in round 1 (including GNINA docking) are computed.

Additionally, for cofolded structures an `is_valid` binary metric is computed, which determines whether the ligand was positioned in the pocket during cofolding. This is assessed by computing the centroid of both the pocket and the ligand (average of their respective atom coordinates) and measuring the distance between them — if below `cofold_threshold`, the cofolding is deemed successful.

A global score for each structure group is computed as in round 1. The three global scores per structure are summed into a joint global score, which is used to select the `top_n_score_final` final candidates.

Through this process, structural quality is assessed across multiple prediction rounds, while novel ligand binding is measured through docking, affinity prediction with GNINA and Boltz, and cofolding predictions.

> **Note:** One current limitation of the pipeline is that it does not assess how well allostery has been preserved. In Allodesigner EP, this will be addressed through energy difference measurements between the two allosteric states, template conditioning, and molecular dynamics simulations.
