## Pipeline description
### Generate redesign info
First, the input structure is processed to gather information relevant to the execution of the pipeline and the evaluation of the results:
- Two kinds of sequences are retrieved from the PDB file: `sequence_coordinates` consists of the residues for which coordinates are found within the files, `sequence_seqres` contains the complete sequence of the protein provided in the SEQRES section of PDB files. In case this section is not present, `sequence_seqres` takes the value of `sequence_coordinates`. This is done to account for missing residues in the structure that can later cause indexing and chain break issues. Other relevant info like sequence length, missing positions... is also gathered
- A DSSP string for the structure in case a secondary structure preserving approach needs to be implemented
- The active site, the region were the redesign will occur is defined either manually by the user (by providing a list), or automatically. In the latter case, a Pymol function extracts a list of all the residues found within a sphere of radius `first_shell_distance` armstrongs centred on the ligand. A second shell, all the residues less than `second_shell_distance`, is also computed. Lastly, any residue indicated by the user specifically to be or not to be redesigned is included or excluded.
-

The active site definition is processed into:

- An RF diffusion "contig map". This is a syntax that tells RFdiffusion which regions must be preserved and how many residues must be designed to connect the regions.
- Ligand MPNN json files that will indicate which residues to be preserved and edited, to introduce a bias towards or against certain amino acids...
### Sampling ligand positions
In their redesign process, both RF diffusion and LigandMPNN use the ligand atoms as context. As a result, the ligand needs to be previously placed in a somewhat reasonable position before redesign. Although docking could be used, it would serve little given that A) the new ligand might differ greatly from the original pocket, and B) the whole pocket is going to be redesigned, rendering the docking not valid. Instead of docking we turn to a sampling approach using RDkit tools.

- First, the structure of the ligand is obtained from a SMILES string using RDkit `MolFromSmiles` and `conformers` low energy conformers are sampled using `EmbedMultipleConfs`.
- Then these conformers are placed in the pocket by aligning with the original ligand (which is later removed).
- Finally, `positions` random slight rotations and translations are applied to each conformer to further explore the design space

After this, a number of PDB files equal to `positions` times `conformers` is obtained and used as an input for RFdiffusion

NOTE: This module can be skipped by providing a folder named `ligand_sampling`

NOTE: This module is not strictly necessary when using RFdiffusion3 with a flexible ligand configuration, since it allows the ligand to move and adapt to the pocket directly in the diffusion process.
### RF diffusion
Three different versions of RF diffusion are implemented to benchmark against each other on the pipeline: RFdiffusion, RFdiffusion All Atom and RFdiffusion3.

The PDBs generated in the ligand sampling or generated by the user are then used as a starting point to generate `num_designs` designs using the contig maps generated in the previous section.

The RF diffusion step can be skipped either by providing a folder containing RFdiffused structures or through the flag `ligandMPNN_only` for a sequence only redesign.

### 1D filter
The sequences produced by LigandMPNN are checked through a 1D filter based on a sliding window. If within the window more than x instances of the same aminoacid are found, the sequence is removed. This is because a known tendency of LigandMPNN to produce streaks of aminoacids like alanine and glutamate. These sequence lack biological sense and must be removed.
