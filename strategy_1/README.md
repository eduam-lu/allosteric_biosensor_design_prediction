# Strategy 1: Allosteric binding pocket redesign
## Strategy description

## Pipeline description
### Generate redesign info
First, the input structure is processed to gather information relevant to the execution of the pipeline and the evaluation of the results:
- Two kinds of sequences are retrieved from the PDB file: `sequence_coordinates` consists of the residues for which coordinates are found within the files, `sequence_seqres` contains the complete sequence of the protein provided in the SEQRES section of PDB files. In case this section is not present, `sequence_seqres` takes the value of `sequence_coordinates`. This is done to account for missing residues in the structure that can later cause indexing and chain break issues. Other relevant info like sequence length, missing positions... is also gathered
- A DSSP string for the structure in case a secondary structure preserving approach needs to be implemented
- The active site, the region were the redesign will occur is defined either manually by the user (by providing a list), or automatically. In the latter case, a Pymol function extracts a list of all the residues found within a sphere of radius `first_shell_distance` armstrongs centred on the ligand. A second shell, all the residues less than `second_shell_distance`, is also computed. Lastly, any residue indicated by the user specifically to be or not to be redesigned is included or excluded.

The active site definition is processed into:

- An RF diffusion "contig map". This is a syntax that tells RFdiffusion which regions must be preserved and how many residues must be designed to connect the regions.
- Ligand MPNN json files that will indicate which residues to be preserved and edited, to introduce a bias towards or against certain amino acids...
### Sampling ligand positions
In their redesign process, both RF diffusion and LigandMPNN use the ligand atoms as context. As a result, the ligand needs to be previously placed in a somewhat reasonable position before redesign. Although docking could be used, it would serve little given that A) the new ligand might differ greatly from the original pocket, and B) the whole pocket is going to be redesigned, rendering the docking not valid. Instead of docking we turn to a sampling approach using RDkit tools.

- First, the structure of the ligand is obtained from a SMILES string using RDkit `MolFromSmiles` and `conformers` low energy conformers are sampled using `EmbedMultipleConfs`.
- Then these conformers are placed in the pocket by aligning with the original ligand (which is later removed).
- Finally, `positions` random slight rotations and translations are applied to each conformer to further explore the design space

After this, a number of PDB files equal to `positions` times `conformers` is obtained and used as an input for RFdiffusion

NOTE: This module can be skipped by providing a folder named `ligand_sampling`

NOTE: This module is not strictly necessary when using RFdiffusion3 with a flexible ligand configuration, since it allows the ligand to move and adapt to the pocket directly in the diffusion process.
### RF diffusion
Three different versions of RF diffusion are implemented to benchmark against each other on the pipeline: RFdiffusion, RFdiffusion All Atom and RFdiffusion3.

The PDBs generated in the ligand sampling or generated by the user are then used as a starting point to generate `num_designs` designs using the contig maps generated in the previous section.

The RF diffusion step can be skipped either by providing a folder containing RFdiffused structures or through the flag `ligandMPNN_only` for a sequence only redesign.
### Ligand MPNN
LigandMPNN produces `MPNN_num_designs` sequences for each given input PDB from the previous step and using the json files generated at the beginning. At this point, the number of sequences is `positions`x`conformers`x`RF_num_designs`x`MPNN_num_design`x`n_batches`. For each input file, sequences are ordered based on their MPNN score, a metric that assesses the model confidence on the prediction and the `top_n_MPNN` sequences are preserved and stored in a pandas dataframe.
### 1D filter
The sequences produced by LigandMPNN are checked through a 1D filter based on a sliding window. If within the window more than x instances of the same aminoacid are found, the sequence is removed. This is because a known tendency of LigandMPNN to produce streaks of aminoacids like alanine and glutamate. These sequence lack biological sense and must be removed.
### ESMfold
The structure of the sequences surviving the 1D filter is predicted using the ESMfold model. ESMfold is an evolutionary based model that is trained to transform sequences into embedding vectors. These vectors will contain structural features that the model recovers to reconstruct full structures. ESMfold is known for its swift predictions at the cost of some accuracy when compared to the most precise models. 
### 3D parameters and filtering 1
**Parameters**

The following params are computed for each ESMfold structure:
- pLDDT, a metric of the confidence the model has on the predicted structure. This is extracted from the B factor field in the PDB files
- RMSD and TMscore with the original structure, to assess too big or too little deviations from the reference structure. This is computed using the tmtools package
- clashes: sometimes predicted structures can contain physically impided regions. To filter those, we compute the clashes found within a structure. Two atoms are considered to be in a clash if the distance between them is too short to be forming an interaction (like hydrogen bonds), but too long to be forming a covalent bond. We use biotite to compute an adjacency matrix, compute the pairwise distance between the atoms and counting how many of them are in a clashing state.

Also, for each structure, the ligand is docked using GNINA. GNina is a docking program that uses a Convolutional Neural Network as a scoring function. Their trained CNNs are comparable in accuracy with traditional force field scoring functions and orders of magnitude faster to execute, allowing high throughput docking of ligands. As of now, the box where poses are sampled is automatically determined by the program. Soon a version constraining the box to the original pocket will be implemented. 

The best pose, the CNNaffinity and CNNscore are also saved as parameters. CNNaffinity is the affinity of the docked complex as determined by the CNN.  The CNNscore is a value between 0 and 1 that is used to rank the poses of the ligand, where a score of 1 denotes a perfect ligand pose.

**Filtering**

First, structures not meeting the minimal tresholds set by `MIN_PLDDT`, `MIN_RMSD`, `MAX_RMSD`, `MAX_CLASHES` are removed from contention.

Then, each metric obtained in the previous step is normalised between 0 and 1. A global score is calculated through a weighted sum of the normalised values using the weights defined in `global_score_weights`. Structures are sorted by global score and the `top_n_score_ESM` are preserved. There's an option to further narrow down the candidates in this step, based on their performance in GNINA through `top_n_GNINA_ESM`.

### Second prediction round (AF3/Chai + Boltz)
The sequences of the structures surviving the first filtering round are subjected to a second structure prediction round that combines Boltz2 and either AlphaFold3 or Chai-1.

Boltz2 is a cofolding model designed to excel at structure and ligand binding pose and affinity prediction. Apart from structure prediction metrics, the model outputs `affinity_pred_value` and `affinity_probability_binary`. `affinity_probability_binary` ranges from 0 to 1 and represents the predicted probability that the ligand is a binder. `affinity_pred_value` aims to measure the specific affinity of different binders and how this changes with small modifications of the molecule.

Then, Alphafold3 and Chai-1 are structural prediction methods with state of the art accuracy. While Alphafold3 also excels in predicting small molecule binding and protein protein interactions, it is also heavily dependent on MSA information, unlike Chai-1. They should be used according to their power and differences.

For each structure, both Chai and AF3 are executed twice: one without ligand to directly assess the quality and precission of the structure, and in a cofolding manner to predict ligand binding and assess modifications in the structure by the presence of the ligand

All the folding models can be given the original template and activate the use of MSAs through their respective flags in the config file.

### 3D parameters and filtering 2
At this stage there are 3 kinds of structures: Boltz, AF3/CHAI and AF3/CHAI cofold predictions. For each group, the same parameters as in the first filtering step (including the GNINA docking) are computed. 

Additionally, for the cofolded structures an `is_valid` binary metric is computed, which determines if the ligand was positioned in the pocket during the cofolding process. This is done by computing a centroid of the pocket and the ligand (average of the coordinates of their respective atoms) and measuring the distance between them. If the distance is lower than the `cofold_treshold`, the cofolding is deemed to have placed the ligand within the redesigned pocket. 

After that, a global score for each structure in each of the structure groups is computed as in the previous filtering step. The three global scores for each structure are added up into a joint global score, which is then used to filter the candidates. The `top_n_score_final` candidates are selected as the best hits produced by the pipeline.

Through this process, we account for structural quality through several structure prediction rounds, but we also measure and assess novel ligand binding through docking, affinity prediction with GNINA and Boltz, and cofolding predictions.

One of the flaws of the pipeline is that it does not account at any step for how well the allostery has been preserved. In the following strategies, apart from measuring new ligand binding, this will be accounted for through measuring the energy difference between the two allosteric states, template conditioning and molecular dynamics simulations
